What it reveals

Things you own
but have never read.

A skill library grows the way a drawer fills. Nothing announces itself, nothing asks to be reviewed, so the set that shapes every answer you get is the one set you have never looked at. Skills Viewer opens the drawer.

  • Which skills are actually here. Not which you meant to write: which are on this machine, right now.
  • What each one still says. Rendered to read, with the fields it declares laid out plainly.
  • Whose it is. Skills you wrote and skills that arrived with a plugin are separated under a heading each, so you can tell instantly which is which.
  • What travels with it. The other files sitting beside the document are named, so a multi file skill says so.
  • What is broken. A skill whose frontmatter will not parse is still listed, with the failure shown rather than quietly dropped.
Everything it does

Your own skills and your plugins' skills, told apart at a glance.

Looking changes nothing.

Skills Viewer never writes to a skill. That is not a promise made in a readme: a structural test reads the whole program and fails the build if any part of it but the settings file calls a writing operation. When you want to change something, it hands the document to the editor you chose and stands back.
